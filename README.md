# Механизмы и загадки

Модуль для [Foundry VTT](https://foundryvtt.com) v13: интерактивные головоломки на сцене. Мастер размещает загадку, игроки её решают, а при успехе или провале модуль запускает действия (сообщение, звук, показ плитки, открытие двери и другие).

Модуль не зависит от игровой системы. Он разрабатывается и проверяется с расчётом на DnD 2024 (система `dnd5e`), но ничего из неё не использует.

> **Статус: этап 1 из 7.** Готов только каркас (хранилище, канал игрок → мастер, настройки, локализация). Самих головоломок и окон пока нет. Модуль можно включить в мире, но видимых функций он ещё не добавляет.

## Планируемые возможности

- **Пятнашки**: поле 3×3, 4×4 и другого размера, перемешивание с гарантированной решаемостью.
- **Поворотные кольца**: настраиваемое число колец и секторов, вращение влево и вправо.
- **Последовательность символов**: порядок нажатий, поведение при ошибке (сброс и другое).
- Привязка загадки к плитке или токену, проверка расстояния, сброс состояния.
- Действия после успеха и провала: сообщение, чат, показ или скрытие плитки, дверь, звук, макрос (макросы выключены по умолчанию).

## Как устроена защита решения

- Публичные данные загадки (название, подсказки, текущее состояние) лежат во flags сцены.
- Правильное решение и действия лежат в скрытом журнале с правами NONE для игроков.
- Игрок отправляет ход или комбинацию мастеру через сокет. Проверка и действия выполняются только на клиенте активного мастера.
- Если мастера нет в сети, загадки не проверяются, игрок видит сообщение об этом.

Известные ограничения:

- Сервер Foundry не подтверждает, какой именно пользователь прислал сообщение сокета, поэтому `userId` в запросе нельзя считать доказательством личности.
- Скрытость журнала с секретами нужно проверить в вашем мире (см. ниже). В документации Foundry я не нашёл прямого подтверждения, что клиент игрока такой документ не получает.

## Установка

### Через Foundry (после первого релиза)

В Foundry: «Add-on Modules» → «Install Module» → вставьте в поле Manifest URL:

```
https://github.com/OWNER/REPO/releases/latest/download/module.json
```

Замените `OWNER/REPO` на ваш аккаунт и название репозитория.

### Для разработки

Папка модуля **обязана называться `mechanisms-and-puzzles`** (так же, как `id` в `module.json`), независимо от названия репозитория:

```bash
cd "<папка данных Foundry>/Data/modules"
git clone https://github.com/OWNER/REPO.git mechanisms-and-puzzles
```

Затем включите модуль в настройках мира. Сборка не нужна: модуль состоит из обычных ES-модулей.

## Проверка после установки

Выполняйте в консоли браузера (F12).

1. **Секреты скрыты от игроков.** Как игрок:
   ```js
   game.modules.get("mechanisms-and-puzzles").api.verifySecrecy()
   ```
   `false` означает, что журнал с секретами игроку не виден. Если вернулось `true`, решение можно прочитать в консоли, сообщите об этом в Issues.
2. **Канал игрок → мастер.** Как игрок, при мастере онлайн:
   ```js
   await game.modules.get("mechanisms-and-puzzles").api.socket.request("ping")
   ```
   Ожидается объект с `pong: true`.

## Структура репозитория

```
module.json            манифест модуля
lang/ru.json           перевод интерфейса
scripts/
  main.mjs             хуки init и ready, настройки, API
  constants.mjs        идентификаторы и общие константы
  storage.mjs          хранение загадок и секретов
  socket.mjs           обмен игрок → мастер
styles/puzzles.css     стили
.github/workflows/     CI и сборка релиза
```

Планируемые каталоги `scripts/puzzles/`, `scripts/apps/` и `templates/` появятся на следующих этапах.

## План разработки

1. Каркас: манифест, локализация, хранилище, сокет (готово).
2. Базовый класс головоломки и «последовательность символов».
3. Пятнашки.
4. Поворотные кольца.
5. Окно мастера, редактор, привязка к объектам, проверка расстояния.
6. Действия при успехе и провале.
7. Стили и проверка прав.

## Выпуск версии

1. Обновите `CHANGELOG.md`.
2. На GitHub создайте релиз с тегом вида `v0.2.0` (с буквой `v`).
3. Workflow `Release` сам подставит версию и ссылки в `module.json`, соберёт `module.zip` и приложит оба файла к релизу.

Поля `version`, `url`, `manifest`, `download` и `bugs` в `module.json` вручную менять не нужно: их заполняет workflow.

## Участие в разработке

Баг-репорты оформляйте через Issues и указывайте версии Foundry, `dnd5e` и список других включённых модулей. Перед отправкой изменений локально выполните те же проверки, что и CI:

```bash
for f in module.json lang/*.json; do jq empty "$f"; done
find scripts -name '*.mjs' -print0 | xargs -0 -n1 node --check
```
