# Механизмы и загадки

Модуль для [Foundry VTT](https://foundryvtt.com) v13: интерактивные головоломки на сцене. Мастер размещает загадку, игроки её решают, а при успехе или провале модуль запускает действия (сообщение, звук, показ плитки, открытие двери и другие).

Модуль не зависит от игровой системы. Он разрабатывается и проверяется с расчётом на DnD 2024 (система `dnd5e`), но ничего из неё не использует.

> **Статус: этап 5 из 7.** Готовы три головоломки (последовательность символов, пятнашки, поворотные кольца), окно игрока, окно мастера, привязка загадки к токену или плитке, проверка расстояния и режим «выключена для игроков». Действия при успехе и провале (сообщения, двери, звук, макросы) ещё не реализованы.

## Планируемые возможности

- **Пятнашки**: поле 3×3, 4×4 и другого размера, перемешивание с гарантированной решаемостью.
- **Поворотные кольца**: настраиваемое число колец и секторов, вращение влево и вправо.
- **Последовательность символов**: порядок нажатий, поведение при ошибке (сброс и другое).
- Привязка загадки к плитке или токену, проверка расстояния, сброс состояния.
- Действия после успеха и провала: сообщение, чат, показ или скрытие плитки, дверь, звук, макрос (макросы выключены по умолчанию).

## Как устроена защита решения

- Публичные данные загадки (название, подсказки, текущее состояние) лежат во flags сцены.
- Правильное решение и действия лежат в скрытом журнале с правами NONE для игроков.
- Игрок отправляет ход или комбинацию мастеру через сокет. Проверка и действия выполняются только на клиенте активного мастера.
- Если мастера нет в сети, загадки не проверяются, игрок видит сообщение об этом.

Известные ограничения:

- Сервер Foundry не подтверждает, какой именно пользователь прислал сообщение сокета, поэтому `userId` в запросе нельзя считать доказательством личности.
- Скрытость журнала с секретами нужно проверить в вашем мире (см. ниже). В документации Foundry я не нашёл прямого подтверждения, что клиент игрока такой документ не получает.

## Установка

### Через Foundry (после первого релиза)

В Foundry: «Add-on Modules» → «Install Module» → вставьте в поле Manifest URL:

```
https://github.com/AlexanderKrauchuk/mechanisms-and-puzzles/releases/latest/download/module.json
```

### На The Forge

Игрокам ничего устанавливать не нужно: модуль ставится на сервер, а клиенты получают его при подключении.

Что подтверждено документацией Forge:

- Forge поддерживает Foundry v13 (поддержка объявлена 13 мая 2025). Убедитесь, что мир работает на v13 и что установленная версия `dnd5e` с ней совместима.
- Собственный модуль загружается через мастер импорта: страница Games Configuration → «Summon Import Wizard», выключить переключатель «Install found packages from the Bazaar», выбрать ZIP или папку, нажать «Analyze».
- После импорта остановите и снова запустите сервер Foundry, затем включите модуль в мире через «Manage Modules».
- Загруженный вручную модуль сам не обновляется. Для каждой новой версии скачайте `module.zip` из релиза на GitHub и импортируйте заново: новая загрузка заменяет установленную версию с тем же ID.

Установка по Manifest URL (рекомендуемый способ): на сайте Bazaar откройте меню «Custom Module» и вставьте ссылку из раздела «Через Foundry». Пакеты, которых нет в Bazaar, расходуют квоту хранилища вашего аккаунта. Репозиторий на GitHub должен быть публичным, а релиз опубликован, иначе Forge не скачает `module.json` и `module.zip`.

Чего я не смог подтвердить:

- Структуру ZIP для мастера импорта. Релизный `module.zip` содержит `module.json` в корне (так принято в Foundry). Если мастер импорта модуль не находит, упакуйте файлы в папку `mechanisms-and-puzzles/` и импортируйте этот ZIP, а о результате сообщите в Issues.

Рекомендация: сначала проверьте модуль в локальном Foundry v13, а потом загружайте на Forge. Проверки через консоль браузера (F12) работают так же, как в обычном Foundry.

### Для разработки

Папка модуля **обязана называться `mechanisms-and-puzzles`** (так же, как `id` в `module.json`), независимо от названия репозитория:

```bash
cd "<папка данных Foundry>/Data/modules"
git clone https://github.com/AlexanderKrauchuk/mechanisms-and-puzzles.git mechanisms-and-puzzles
```

Затем включите модуль в настройках мира. Сборка не нужна: модуль состоит из обычных ES-модулей.

## Проверка мастером внутри Foundry

Все функции модуля, и новые, и уже готовые, проверяются из окна управления. Макросы не нужны.

### Как открыть окно управления

Любым из трёх способов:

1. Кнопка с пазлом в левой панели инструментов сцены (в группе «Токены», внизу). У игроков на этом месте кнопка «Загадки рядом».
2. «Настройки» → «Настройки модулей» → «Механизмы и загадки» → «Открыть окно управления».
3. Консоль браузера (F12): `game.modules.get("mechanisms-and-puzzles").api.openManager()`

Окно показывает загадки текущей сцены и само обновляется при их изменении. Внизу окна блок «Диагностика» (версии, активный мастер, игроки в сети, состояние хранилища секретов).

### Проверки за игрока (второй браузер)

Нужны, чтобы проверить то, что мастер в одиночку проверить не может: связь «игрок → мастер» и скрытость решения. Войдите вторым браузером (или в окне инкогнито) под учётной записью игрока, мастер при этом остаётся в сети.

1. Откройте консоль (F12) и выполните: `game.modules.get("mechanisms-and-puzzles").api.verifySecrecy()`. Должно вернуть `false`. Если вернулось `true`, решения видны игрокам.
2. Выполните: `await game.modules.get("mechanisms-and-puzzles").api.socket.request("ping")`. Должен вернуться объект с `pong: true`.
3. Игрок открывает окно загадки командой `game.modules.get("mechanisms-and-puzzles").api.openPuzzle("Название загадки")`. Ход игрока должен сразу отразиться у мастера и наоборот.
4. Игрок не видит кнопки в панели инструментов и пункта настроек, а `api.openManager()` у него выдаёт «Это действие доступно только мастеру».
5. Если мастер выйдет из мира, ход игрока даёт сообщение «Мастер сейчас не в сети…».
6. Расстояние. Привяжите загадку к токену или плитке, поставьте расстояние 10, у игрока должен быть свой токен на сцене. Откройте у игрока «Загадки рядом» (кнопка в панели слева или `api.openList()`):
   - токен игрока дальше 10 единиц от объекта: у загадки пометка «Вы слишком далеко: … нужно не больше 10», кнопка «Открыть» недоступна;
   - подведите токен ближе (расстояние считается между краями, касание даёт 0): пометка исчезла, загадка открывается, ходы проходят;
   - отведите токен, не закрывая окно загадки: вверху окна появляется замок с пометкой, а ход выдаёт «Вы слишком далеко», состояние не меняется.
7. Режим «Выключена для игроков» убирает загадку из списка игрока. Если окно уже было открыто, ход даёт «Эта загадка сейчас недоступна».
8. У игрока без токена на сцене при заданном расстоянии ход даёт «У вас нет токена на этой сцене…». Если привязанный объект удалили, игрок видит «Привязанный к загадке объект не найден».

### Если что-то не открылось

Эти места я не смог проверить в самом Foundry, они написаны по документации v13. Если одно из них не сработало, остальные способы всё равно работают.

- Кнопка в панели инструментов: структура `getSceneControlButtons` в v13 подтверждена документацией, но поведение кнопки я не проверял. Запасной путь: пункт настроек или `api.openManager()`.
- Пункт в настройках модуля: документация `registerMenu` не подтверждает, что можно указать класс на `ApplicationV2`. Запасной путь: кнопка в панели или `api.openManager()`.
- Окно редактора использует форму `ApplicationV2` (`formData.object`), окно подтверждения удаления использует `DialogV2.confirm`. `DialogV2.prompt` в документации подтверждён, а `confirm` я отдельно не сверял.
- Определение «токен принадлежит игроку» (`Actor#testUserPermission(user, "OWNER")`), `scene.grid.size` и `scene.grid.distance`: написаны по моему знанию API, на живом Foundry не проверялись. Симптом, если не так: у игрока при заданном расстоянии всегда «У вас нет токена…».
- «Показать на сцене»: `canvas.animatePan` и `canvas.ping`. Вызываются с проверкой наличия, при отсутствии просто ничего не происходит.
- Выделение объектов для привязки (`canvas.tokens.controlled`, `canvas.tiles.controlled`).
- Открыть загадку кликом по токену или плитке нельзя: в документации v13 я не нашёл подтверждённого хука клика, поэтому игрок открывает загадку из окна «Загадки рядом».
- Присылайте текст ошибки из консоли (F12), я исправлю.

### Привязка и расстояние

- Загадку можно привязать к одному токену или одной плитке текущей сцены. Привязка запоминает id объекта, поэтому при удалении объекта загадка остаётся, а в окне мастера появится «объект не найден».
- Расстояние считается по прямой между краем ближайшего токена игрока и краем привязанного объекта, в единицах сцены (футы, метры). Стены, высота и правила диагоналей сетки не учитываются.
- «Токены игрока» это токены сцены, где игрок владелец персонажа.
- Проверку делает мастер при каждом ходе, окно игрока только показывает подсказку. Мастер на своём клиенте расстоянием не ограничен, чтобы мог проверять загадку из любого места.
- Важно: сервер не подтверждает, какой пользователь прислал сообщение сокета, поэтому проверка расстояния защищает от случайного и честного нарушения, но не от игрока, который сознательно подделывает сообщения.

### Как работают поворотные кольца

- У каждого кольца одинаковое число секторов. На каждом секторе подпись (по умолчанию числа 1, 2, 3...). Подписи можно задать свои, до 6 символов, общие для всех колец или отдельные для каждого.
- Сверху находится метка. Решение это для каждого кольца подпись, которая должна оказаться у метки. В форме решение записывается номерами подписей, например `3 1 5` (первое число относится к внешнему кольцу).
- Начальное положение случайное и никогда не совпадает с решением.
- Режим «после каждого поворота»: загадка решается, как только комбинация совпала. Игрок не получает подсказок вроде «тепло», поэтому подобрать решение можно только перебором. Режим «по кнопке»: игрок сам нажимает «Проверить». Вместе с провалом при ошибке перебор теряет смысл, потому что неверная проверка запускает действия при провале (они появятся на этапе 6).
- Длинные подписи при пяти кольцах и двенадцати секторах мелкие. Если подписи не читаются, уменьшите число секторов или колец.

### Те же действия макросами

Для автоматизации в консоли и макросах доступно API:

```js
const api = game.modules.get("mechanisms-and-puzzles").api;
api.openManager();                                    // окно управления (мастер)
api.openList();                                       // «Загадки рядом» (игрок)
api.listPuzzles();                                    // публичные данные загадок сцены, без решений
api.openPuzzle("Название");                           // окно игрока по названию или id
await api.engine.resetPuzzle(canvas.scene, "<id>");   // сброс
await api.engine.nearSolve(canvas.scene, "<id>");     // подготовка к последнему ходу
await api.engine.deletePuzzle(canvas.scene, "<id>");  // удаление
await api.engine.createPuzzle(canvas.scene, {         // создание
  type: "rings",
  name: "Диски",
  config: { rings: 3, sectors: 6, checkMode: "auto" },
  solution: [2, 0, 4],                                // положения колец с нуля
  interaction: { mode: "ui", maxDistance: 10 },       // необязательно
  link: { kind: "token", id: "<id токена>" }          // необязательно
});
```

## Структура репозитория

```
module.json              манифест модуля
lang/ru.json             перевод интерфейса
scripts/
  main.mjs               хуки init и ready, настройки, API
  constants.mjs          идентификаторы и общие константы
  storage.mjs            хранение загадок и секретов
  socket.mjs             обмен игрок → мастер
  engine.mjs             проверка ходов и изменение состояния (на стороне мастера)
  puzzles/
    base.mjs             контракт типа головоломки и реестр типов
    sequence.mjs         последовательность символов (чистая логика)
    sliding.mjs          пятнашки: ходы, перемешивание, проверка решаемости (чистая логика)
    rings.mjs            поворотные кольца: ходы, проверка, геометрия для SVG (чистая логика)
  access.mjs             привязка, режим взаимодействия и расстояние (чистая логика)
  proximity.mjs          поиск привязанного объекта и токенов игрока на сцене
  access-text.mjs        текст о причине недоступности загадки
  editor-data.mjs        перевод данных формы редактора в описание загадки и обратно
  apps/
    player-app.mjs       окно загадки для игрока
    gm-manager.mjs       окно управления для мастера
    puzzle-editor.mjs    окно создания и изменения загадки
    puzzle-list.mjs      окно «Загадки рядом» для игрока
templates/               шаблоны Handlebars
styles/puzzles.css       стили
tests/                   тесты (Node, без Foundry)
.github/workflows/       CI и сборка релиза
```

Каталог `scripts/puzzles/` не обращается к глобальным объектам Foundry, поэтому логику головоломок можно тестировать в обычном Node.

## План разработки

1. Каркас: манифест, локализация, хранилище, сокет (готово).
2. Базовый контракт головоломки и «последовательность символов», окно игрока (готово).
3. Пятнашки с гарантированной решаемостью (готово).
4. Поворотные кольца, окно управления мастера, редактор загадок, диагностика (готово).
5. Привязка к плитке или токену, проверка расстояния, режим «выключена» (готово).
6. Действия при успехе и провале.
7. Стили и проверка прав.

## Выпуск версии

1. Обновите `CHANGELOG.md`.
2. На GitHub создайте релиз с тегом вида `v0.2.0` (с буквой `v`).
3. Workflow `Release` сам подставит версию и ссылки в `module.json`, соберёт `module.zip` и приложит оба файла к релизу.

Поля `version`, `url`, `manifest`, `download` и `bugs` в `module.json` вручную менять не нужно: их заполняет workflow.

## Участие в разработке

Баг-репорты оформляйте через Issues и указывайте версии Foundry, `dnd5e` и список других включённых модулей. Перед отправкой изменений локально выполните те же проверки, что и CI:

```bash
for f in module.json lang/*.json; do jq empty "$f"; done
find scripts -name '*.mjs' -print0 | xargs -0 -n1 node --check
node --test "tests/**/*.test.mjs"
```

Тесты используют заглушку Foundry (`tests/helpers/mock-foundry.mjs`). Она проверяет логику модуля, но не заменяет проверку в настоящем Foundry.
